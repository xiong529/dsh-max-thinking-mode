## 二、任务 1 · 访客预览功能设计

**任务内容**：设计一个未登录访客可只读预览文档的功能，访客绝无写权限，且看不到任何内部路径、ID、目录结构等元数据。

**标准模式**（方案质量 4 / 突破点 4）：
- 核心思路：访客看到的不是原文档，而是重新渲染的"投影"；授权面收敛为一张令牌映射表。
- 突破点：①投影而非透传 ②授权面单映射 ③存储层只读账号物理隔离 ④元数据登记制（默认不可见）。
- 局限：方案完整但机制偏常规，没有标准组未见过的新颖做法。

**最大思考模式**（方案质量 5 / 突破点 7）：
- 在标准模式思路上新增三个真正的独立创新：
  - **能力寻址**：令牌只存哈希、与内部 ID 不可逆关联（引用 W3C capability URL 规范）；
  - **高敏档栅格化渲染**：敏感文档渲染为图片/PDF，不可选字、无源文件、禁复制；
  - **POST 打开**：高敏场景令牌走 POST body 交付，不进 URL、浏览器历史、代理日志。
- 额外做了对外调研（web 搜索），并给每条防御配了验收测试（威胁模型即测试套件）。

**结论**：突破点 7 vs 4 明显胜出；增量是标准组没想到的新机制，不是篇幅更长。

## 三、任务 2 · 迁移手写权限系统

**任务内容**：代码库各调用点散落手写角色检查，必须替换为统一权限模型，且不允许新旧系统并存的"迁移窗口"。

**标准模式**（方案质量 5 / 突破点 5）：
- 核心洞察：把"替换两套系统"重构为"一条接缝上的单点切换"——旧逻辑压缩进统一接口的初始实现，收敛（琐碎）与语义替换（风险）分离。
- 突破点：①单接缝原子切换 ②语义与语法分离 ③语料重放+差分证明 ④授权污点分析 ⑤回滚=整体回退而非并存。

**最大思考模式**（方案质量 5 / 突破点 7）：
- 方案核心同构（收敛+原子切换+分层证明），这是该问题形态下的正确解，两种模式都找到了。
- 最大思考的增量：
  - **反向差分**：新模型绝不放行旧模型拒绝过的输入（主动攻击"错放行"方向）；
  - **强制执行 Tripwire**：敏感操作无决策记录即拒绝+告警，把"漏检查"从 fail-open 转成 fail-closed；
  - 调用了 `isolated_review`，最终立场带两轮对抗评审痕迹，并对"零漏洞不可判定"做了诚实声明。

**结论**：方案质量持平（5 vs 5）；突破点 7 vs 5，增量是对抗评审产出的反向差分与 Tripwire。

## 四、任务 3 · 客户端离线渲染带公式的 Markdown

**任务内容**：客户端离线渲染带 LaTeX 数学公式的 Markdown，**禁止使用任何现成库**（KaTeX/MathJax 等），并要证明方案可行。

**标准模式**（方案质量 4 / 突破点 4）：
- 方案：自研 TeX→MathML 子集转译器（约 300 行）+ 浏览器原生 MathML Core 排版。单文件 `index.html`。
- 验收（独立复现）：真实浏览器运行，几何断言 **38/38 通过**，0 网络请求、0 JS 错误。

**最大思考模式**（方案质量 5 / 突破点 6）：
- 方案：自研 Markdown/LaTeX 双解析器 + **双后端**——MathML Core 主路径 + **自研 SVG 盒式排版兜底**（完全不依赖平台数学引擎的保险路径，标准组没有）。
- 额外：内嵌 STIX 数学字体（防无字体机器退化）、自动后端探测、未支持语法渲染为红框提示不崩溃。
- 验收（独立复现）：单测 **76/76**、浏览器几何 **27/27**、像素级 **13/13** 全部通过。
- 代价：单文件 1.2MB（含内嵌字体），是标准组 47KB 的 25 倍；工具调用 186 vs 44。

**结论**：最大思考方案更稳（双保险）、证据更全（三套自动化验证），代价是更大体量。若按轻量场景论，标准组更简；按可靠性论，最大思考胜出。

## 五、任务 4 · 突破热点锁性能瓶颈

**任务内容**：任务队列 60% 时间花在争夺同一把锁上，常规分片无效（热点键唯一），要求给出非常规分片思路。

**标准模式**（方案质量 4 / 突破点 4）：
- 方案：组合提交（Flat Combining × Group Commit）——把锁的获取次数从 O(任务数) 摊销到 O(批次数)。纯文档论证，无实测数据。

**最大思考模式**（方案质量 5 / 突破点 6）：
- 同一核心方向，但**构建了可运行的全矩阵基准**（真实多线程 + 共享内存原子操作 + 计数全量校验防作伪）：
  - 16 线程下组合批处理 **13–30 倍**于互斥锁（我独立复现确认：18.3M / 41.9M vs 1.4M ops/s）；
  - **负载类别意识**：区分"可聚合"与"严格串行"两类负载，实测并诚实标注——组合提交只在可聚合负载有效，严格串行负载下退化为互斥锁水平（此时乐观 CAS 更好）。
- 调用了 `isolated_review`×3（四场中对抗信号最强）。

**结论**：方案方向两模式一致；最大思考的增量是把方案做成可运行、可复现的证据，并诚实标注了方案不适用的负载边界（标准组文档未充分强调）。

## 六、任务 5 · 从零发明全新功能

**任务内容**：产品需要一个别处没有的协作功能：一群人在共享画布上工作，但每人看到的"当前状态"可以不同（有人看草稿、有人看已确认版），系统自动合并修改且不丢任何人的意图。

**标准模式**（方案质量 4 / 突破点 5）：
- 方案（棱镜画布）：对象粒度版本阶梯（草稿→提出→确认→废弃）+ 意图骨架 + 三类合并判定 + 谈判票 + 可复活保险。

**最大思考模式**（方案质量 5 / 突破点 7）：
- 两模式不约而同设计了同一方向（强信号：该问题收敛到同构解）。
- 最大思考的增量：
  - **真实先例调研与缺口论证**：逐一对照 CRDT、Upwelling（Ink & Switch 2023）、Backstitch、Figma 分支、建议模式、MVCC，提炼"三个本质缺口"——标准组只有抽象矩阵，没有针对真实产品的证据；
  - **合并目标从"值"升级到"意图"**："数据不丢 ≠ 意图不丢"，干预位置放在状态折叠函数上；
  - **意图翻译**（可逆署名，一键还原）+ **决策节点**（平行真相，丢意图在结构上不可能）；
  - **对象级共改触发**与**确认锚定评审快照**——这两个关键机制修正标注为两轮对抗审查（`isolated_review`×2 + 仲裁）的直接产出，标准组一次性成稿未经历此轮重构。

**结论**：这是 `isolated_review` 对抗价值最直接的一场——对抗审查挑出 6 处缺陷并逼出两个关键机制修正。

## 七、总体结论

**最大思考模式按设计工作，在目标维度（突破强度）上五战全胜。**

| 判读维度 | 实测结果 |
|---|---|
| 突破强度 | 每场都胜出：7/7/6/6/7 vs 4/5/4/4/5，累计 **33 vs 22** |
| 方案质量 | 5 胜 0 负 1 平（任务 2 持平） |
| 可行性 | 相当或略优（任务 3 双后端、任务 4 实测证据、任务 5 可测路线图） |
| 成本 | 约 1.3–2 倍 token（任务 1/2）；任务 3/4 因验证迭代更充分成本更高 |

**最大思考模式独有的、被实测确认的行为**：
- 对外取证（web 搜索 / 网页抓取）——标准模式几乎为零；
- `isolated_review` 对抗审思——任务 2（1 次）、任务 4（3 次）、任务 5（2 次+仲裁）均发生，次数随决策重要性上升；任务 5 中直接产出两个关键机制修正；
- 把"方案"做成"可运行的证据"——任务 3 双后端原型、任务 4 全矩阵基准，均提供可复现验证；
- 探索足迹与显式回溯；
- 诚实边界声明——任务 4 的负载类别差异、任务 5 的"意图不丢≠意图在结果中成立"。

**诚实的注记**：五场中有两场（任务 2、5）两种模式方向收敛到同构方案。此时最大思考的增量不在"更正确的答案"，而在**验证深度、边界诚实度与对抗修正**——这正是评估协议要求的"方案优劣与突破点强度，而非代码正确率"。

**定位**：最大思考模式是"难题专用"工具——适合没有现成答案、第一直觉多半是错的创新任务；日常熟路任务用标准模式更快更省。

- 局限：除任务 3 外为单场采样；建议每任务各跑 3 次取中位数复核；有条件时对模式盲评（第二人打分）。
